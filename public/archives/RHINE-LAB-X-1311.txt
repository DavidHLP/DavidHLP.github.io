単一の変換を速くすることやスレッド数を増やすことは、中断復旧・再実行・照合が可能なバッチ抽出や巨大表変更の代替にはならない。大規模データ処理の基準は「1 回成功した」ではなく、**重複・漏れのない範囲設計、中断後の再開可能性、再実行時の冪等性、結果の照合可能性**である。

## Kettle / PDI：段階別の特定を先に行い、分割抽出へ進む

### 1. 入力・変換・出力でボトルネックを切り分ける

並列度や JVM ヒープを上げる前に、各段階の行数、スループット、待ち時間、資源使用量を観測する：

- **入力段階**：必要列だけを選択し、可能なフィルタは DB 側へ押し込む。「入力行ごとにクエリを実行」が誤って有効になっていないか確認し、一括読み取りが大量の細粒クエリへ崩れるのを防ぐ（Table Input の SQL パラメータと行単位設定をタスク意味に合わせる）。
- **変換段階**：反復 DB 参照、不要な型変換、重いスクリプト、大規模ソートを個別に測る。ステップ複製を増やす前に、順序・グループ化・重複排除を壊さないか確認する。
- **出力段階**：`Commit size`（トランザクション確定までの行数）と `Use batch update for inserts`（バッチ INSERT 送信）を区別する。チェックを入れてもドライバや周辺ステップ設定で無効化されることがあるため実効性を確認する。コミット単位は大きいほど良いわけではなく、スループット・メモリ・やり直しコスト・対象 DB 負荷を比較する。

### 2. 大量抽出における復旧と照合の設計

一度限りの大量抽出では、安定した主キー範囲や固定時間窓による明示的分割を用い、各分割の始点・終点・状態・出力件数・リトライ回数を重複や漏れなく管理する：

- 再起動後は完了確認済み地点から続行し、対象側の一意キー・冪等書き込み・ステージングマージでリトライを受け止める。
- ソースが更新され続ける場合は一貫性の基準時点を定義する。最大主キーの記録だけでは過去行の更新・削除を捕捉できず、スナップショットの代替にならない。スナップショットと増分の接続を設計し、分割件数・重要集計値・サンプル行を照合する。

## MySQL / InnoDB 巨大表の変更：範囲を狭めてからコストを制御する

数十億行規模の表では、影響行数、インデックス・パーティションによる絞り込み可否、オフライン可否、継続書き込みの有無、ロールバック要件を先に確認する：

| 操作 | 検討できる手法 | 主に制御すべきリスク |
| --- | --- | --- |
| 大量削除 | 境界付き分割削除；削除率が高い場合は残存データのコピー切替も評価 | ロック、ログ、ディスク容量、障害復旧 |
| 大量更新 | ステージング表で検証後に範囲限定で結合更新を分割実行 | 一意マッチ、ロック競合、トランザクション規模 |
| 大量挿入 | バッチ書き込み、または適切な一括ロード手法 | 制約整合性、インデックス保守、対象 DB 負荷 |

2 つの厳守境界：

- **高削除率での「残存データコピー + 表切替」は完全なデータ移行として扱う**：コピー中の増分書込、オブジェクト依存、インデックス・制約、切替窓、チェックサム、ロールバックを揃える必要があり、コピーと改名文だけでは不完全である。
- **`TRUNCATE TABLE` を「より速くロールバック可能な DELETE」と誤認しない**：MySQL では `TRUNCATE TABLE` は暗黙コミットされ、通常のトランザクションロールバックで戻せず、`WHERE` 条件も指定できない。小さな制御範囲で正しさを確認してから、ロック待ち・ログ・レプリケーション負荷に応じてバッチを調整し、異常時は停止または範囲縮小を行う。

## 証拠の境界と未検証項目

- **出典の事実**：本ページは [データベース筆記試験の復盤](/blog/legacy/note/ja/database-written-test-review/) 第 7・8 節から分離され、`database-written-test-review` スナップショットと引用元の PDI（Table Input / Table Output / Performance Tips）および MySQL 8.4 文書（`DELETE`・`UPDATE`・`TRUNCATE TABLE`・InnoDB 一括ロード）を根拠とする。
- **未検証項目**：今回の作業では固定版の PDI や MySQL 8.4 実機で分割中断・再開・照合・ベンチマーク・表切替を実行していないため、速度倍率や無停止切替は主張できない。

## 昇格チェック

- 固定版の PDI と対象 DB 上で、分割抽出の中断・再開・重複排除・件数/集計照合の演習を実施する
- 制御された MySQL 8.4 テスト表で境界付き分割削除・更新のロック待ちとバッチ調整、および `TRUNCATE` の暗黙コミット非ロールバック境界を確認する
- 表切替候補の停止・ロールバック前提と増分検証チェックリストを補い、親ページとの双方向リンクを維持する
